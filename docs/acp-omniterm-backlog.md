# OmniTerm ACP 层对照与未吸收清单

对照来源：`/home/pax/coding/OmniTerm-dev`（Rust + `agent-client-protocol` crate，ACP 层在 `src/acp` + `src/ws/acp.rs`，约 15.5k 行）。首次对照 2026-10-11；2026-10-17 拉 dev 到 `6a13ecb8` 复核并吸收第 4 条；2026-10-27 再拉到 `605c8507` 全量复核（本文「尚未吸收」自此带优先级）。产品形态与本插件同构：借一个界面壳，经 stdio ACP 驱动外部 agent 进程。本文记录四件事：对照结论、**已吸收**的改动、**尚未吸收**的候选项（按优先级排序，含 OmniTerm 侧的文件与符号，供未来认领时定位），以及**明确不吸收**的项（附理由，防止未来误判为遗漏）。

OmniTerm 侧的关键文件：`src/acp/client.rs`（ACP 客户端与广播总线）、`src/acp/turn_accumulator.rs`（后端权威的 turn 折叠与记账）、`src/acp/agent_proc.rs` / `supervisor.rs` / `reaper.rs`（进程生命周期）、`src/acp/permission.rs`（审批）、`src/acp/resolve.rs`（命令解析 + npm 私有 prefix）、`src/acp/terminal.rs` / `async_tasks.rs`（终端与后台任务）、`src/acp/title.rs`（agent 侧标题回填）、`src/acp/chat_persistence.rs` / `usage.rs` / `config_prefs.rs`（持久化）、`src/ws/acp.rs`（WS 重连对账）。该仓的注释纪律很好：大量实测事故以注释形式钉在符号旁边，认领候选项时值得把对应注释读一遍。

## 对照结论

主干能力两边重合：stdio JSON-RPC 桥、启动超时杀进程、cancel 兜底强制定稿、`session/load` 崩溃恢复、空闲回收、审批 UI、模型/配置目录、turn 折叠渲染。**Windows 上本插件更完整**：OmniTerm 的 ACP 层曾明确标注「POSIX-only」（2026-10-17 已勘误为「协议支持 Windows、缺的是本项目自己的五类适配」：`.cmd` 解析、workspace cwd、Job Object 进程树、HOME/USERPROFILE、hook 语法，Windows 桌面版计划仍是设计稿）；本插件的 `cmd.exe /d /s /c` + `taskkill /t /f` 组合（约束 26）是落地方。OmniTerm 更强的地方：① agent 侧会话历史管理（`session/list` / `session/delete` / 标题回填，2026-10-04~16 四轮落地）；② 后端权威的 turn 记账与告知归位（work_ms/wait_ms、权限超时告知的 turn 归属）；③ 后台任务对空闲回收的保护（JetBrains AIR 扩展帧）。这些与本插件的架构归属不同之处见「明确不吸收」，协议面缺口见「尚未吸收」。

## 已吸收（前三条 2026-10-11 同日落地，见约束 12 / 23；第 4 条 2026-10-17；第 5 条 2026-10-27 复核时发现已落地）

1. **取消兜底的 turn 世代守卫 + `settled` 闸门解开**。OmniTerm 的 `spawn_cancel_turn_fallback` 用 `prompt_generation` 守卫兜底定时器——定时器触发时 running 的可能已经是取消之后新发起的 turn。本插件落点：`armCancelFallback` 捕获 `session.turnSeq`，世代前进即放手；强制定稿同时解开 `settledResolve`（否则适配器路径的下一轮 prompt 卡 `unsettled`）。
2. **粘滞取消吞消息的检测重发**。OmniTerm 实测 codebuddy 2.161.4：处理 `session/cancel` 时异步清理状态，落在清理窗口内的下一条 prompt 被秒回 `cancelled`（复用旧 requestId、不生成 turn），用户消息无痕丢失；判据是「本世代是否发起过 cancel」而非延时。本插件落点：`runPrompt` 的 `cancelRequestedAtTurn` 对比 + `staleCancelRetryDelayMs`（默认 600ms）有界重发。
3. **正常结束却零可见产出的显式报出**。OmniTerm 实测 pi-acp 把 provider 403 折叠成合法 `end_turn`，聊天流只剩空气泡；它按「协议说成功但一个可见帧都没有」判定异常终态（`update_is_visible_output`）。本插件落点：`streamPrompt` 的 `sawVisibleBlock` 记账 + 空产出告警文本块。
4. **对话前就能选好 agent 的模型 / 思考等级，并把选择持久化**（2026-10-17 吸收，OmniTerm 侧 `src/acp/config_prefs.rs` + `attach_config_prefs` / `restore_config_prefs`）。OmniTerm 的记录分两层：agent 级偏好（新建/恢复会话的默认值）与会话级覆盖（本会话用户主动 set 过的值），restore 时合并、逐项用 agent 当前的 `configOptions` 校验，过期项跳过而不是报错。
   - **移植动机**：本插件的模型/思考等级原本只写进**活会话**（`alignSessionConfig`），而活会话要等第一条消息才存在 —— 于是「对话前选模型」根本无法表达，重启后选择也全丢（`chatAgentIntent` 只有内存）。这不是缺个界面，是缺一个**选择属于会话而非进程**的记录。
   - **本插件落点**：`AcpConversationChoice`（`src/protocol.ts`）记录 `agentId` + `modelId` + `effort`，持久化在 `~/.dsh/dsh-ntr/agents.json` 的 `conversations` 键下（`loadPersistedChoices` / `persistAgents`）。`setChatSessionModel` / `setChatSessionEffort` 先记 pick 再对活会话对齐；`applyChatChoice` 在 `createSession` / `getOrCreateDshSession` 的 resume 分支把 pick 应用到**刚物化**的会话上——`session/new` 回的是 agent 自己的默认值，不补这一步「选了 A 却跑了 B」。
   - **与 OmniTerm 的差异（有意）**：不做 agent 级偏好层。agent 级默认已经由 `agent/catalog` 的 `reasoning.defaultEffort` 与 agent 自己的 `currentValue` 表达，再加一层会变成「用户没选过、却以为选过」的第三种事实源。会话级记录 + agent 自报默认足够。
   - **校验语义沿用**：`alignSessionConfig` 本来就只在 `choices` 里含有该值时才下发（`choices.length === 0` 时放行，即 agent 未提供列表不阻断），过期 pick 降级为告警而非失败轮次。
5. **agent 命令的 npm 懒安装**（2026-10-27 复核发现已落地，形式与 OmniTerm 不同）。OmniTerm 的 `resolve_command`（`src/acp/resolve.rs`）解析链：PATH → `~/.omniterm/agents/node_modules/.bin/` → 按 agent 配置的 `npm_package` 装进**私有 prefix** 后复查。本插件落点：`ensureAgentExecutable` + `npmInstallGlobal`（`src/bridge.ts`）+ agent def 的 `npmPackage` 字段——PATH 找不到时 `npm install -g` 再查一次，安装输出进 agent 日志。**保留的差异**：本插件装全局（会进用户全局 npm、需要全局写权限），OmniTerm 装私有 prefix（不污染全局、权限自足）。私有 prefix 形态与约束 28「运行时落盘只在 `~/.dsh/dsh-ntr/`」同向，列为低优先候选，见「尚未吸收」第 9 条。

## 尚未吸收（按优先级排序的候选项，2026-10-27 全量复核）

1. **agent 侧会话历史：`session/list` 未接入（P0）**。OmniTerm 侧 `src/acp/client.rs` 的 `list_sessions(cwd, cursor)` + `GET /agents/{id}/acp-sessions` + Sidebar「Agent 历史」面板（`2026-10-04-acp-session-history-management.md` Phase 1 + E1，2026-10-16 落地）。本插件现状：`session/list` 零引用；浏览器侧只能看到本插件亲手创建的会话，用户在 agent CLI 里跑的历史既不能枚举也不能载入。**SDK 无障碍**：`@agentclientprotocol/sdk` 1.9.0 已导出 `methods.agent.session.list` / `.delete` / `.fork`，无需升级依赖（OmniTerm 自己也握 `ProtocolVersion::V1`，无版本落后）。可复用的落点：`probeConfigOptions` 的短命进程模式（注意它发 `session/new`——OmniTerm D4 实测 opencode 会因此在 agent 历史里留一条 `New session - <时间>` 空行，list 面板会看到自己掺进去的数据，探针化时须决策）、NTR 设置面板加「Agent 历史」区。OmniTerm 的四条约束值得照抄：list 双上限（条数 + 页数，单页条目数由 agent 定）；`title` 缺省 ≠ 清除；不做能力 gate（`-32601` 原文透出）；探针不发 `session/new`。**顺带的标题通道缺口**：本插件只接 live `session_info_update.title`（`bridge.ts` 的 `applyDerived`），而 OmniTerm 2026-10-16 五实现实测表明 opencode / qodercli **从不发** live 标题、只有 `session/list` 给——两条通道没有一条对所有 agent 可用，只接一条 = 对一半 agent 永远没有标题。
2. **agent 侧会话记录删除：`session/delete` 未接入（P1）**。OmniTerm 两段式（`2026-10-09` 勘误 E-11）：进程活着就地发，未驻留立即回 `pending` 再由客户端带 `cwd` 补发、后端临时拉起短命进程现场 gate 能力位后补删；能力判据只认 initialize 响应的 `sessionCapabilities.delete`（marker 结构，未声明不盲发）；文案只说「从 agent 会话列表移除」（软硬删由实现决定）。本插件现状：删 DSH 会话不碰 agent 侧记录，agent 的 `~/.<agent>/projects/<cwd>/<id>.jsonl` 永久残留；且宿主拥有会话删除，插件拿不到删除钩子，入口只能放设置面板（按 agent 清理其历史）。OmniTerm 的五实现实测表（opencode / pi-acp / omp / qodercli / codebuddy）在 `docs/reference/acp-protocol-reference.md` §17.3，认领时直接引用。
3. **回合内宿主告知不进对话（P1，新增）**。OmniTerm 的 `2026-10-26-perm-notice-turn-attribution.md`：权限超时等宿主告知做成 turn 归属的内联帧（pin 化豁免驱逐 + 独立行 `turn_row_id` 归块进过程容器），长回合不再沉底。本插件现状：`agent/notice` 广播只写 store 的全局单槽 `notice`（`client/store.ts`），仅设置面板顶部渲染（`panel.tsx`），**对话里零可见且后写覆盖先写**——`bridge.ts` 权限兜底触发时那条「错过了什么」的告知，正在看对话的用户看不到。落点：NTR 视图已有 `kind: 'notice'` block 形态（`acp-view.tsx`），把回合内 notice 改成按会话进 block；无活跃会话的告知维持现状。
4. **后台任务被空闲回收误杀（P2，新增）**。OmniTerm 的 `src/acp/async_tasks.rs`：解析 JetBrains AIR 扩展帧（`async_task_spawned` / `async_task_progress` / `async_task_state_update`，须在 initialize 的 `_meta.jetbrains.air.capabilities` 显式声明 `asyncTasks` 才会收到），有界注册表（256 条 + 200 字符文本上限），`is_idle_stale` 读 `has_active`——2026-10-19 正式库事故：turn 已 `end_turn` 但后台 Workflow 还在跑，reaper 按空闲阈值杀了进程连带任务。本插件现状：不声明该能力（agent 干脆不发），约束 19 的空闲释放只认 turn / 取消 / 审批 / mode·config 在途 / 探测 / resume / 启动，**没有「后台任务在跑」这一维**。触发 agent：Claude / CodeBuddy 适配器（OmniTerm 注释实证）。
5. **Transcript 的字节上限（双轴淘汰 + 单帧上限）（P3）**。OmniTerm 的帧窗口同时受条数（`MAX_FRAMES` 2000）与字节（`MAX_BLOCKS_BYTES` 128KB）约束，另有单帧上限 `MAX_FRAME_BYTES`（64KB，防单帧独占预算）；正文走 `BoundedText`（head 冻结 + 尾窗 + 显式「已省略 N 字符」标记）。实测依据：codebuddy 每个 `tool_call_update` 都重发完整 `rawInput`（中位 4.5KB/帧），纯条数上限在这种帧下拦不住体积。本插件现状：`Transcript`（`src/impl.ts`）只按条数封顶（`transcriptMaxEntries` 默认 600，肥帧下约 2.7MB），且 SSE 重连 `since()` 一次全量补发。触发条件：重连补发可观测变慢、或内存曲线异常时再做；落地时双轴 + 单帧三限一起上。
6. **ACP `terminal/*` 服务端实现（P4）**。OmniTerm 的 `AcpTerminalManager`（`src/acp/terminal.rs`）实现全部五个终端方法（create / output / kill / release / wait_for_exit），agent 发起的后台命令在聊天里渲染成行内芯片（否则对用户不可见），且后台命令运行中不被空闲回收、纳入 Windows Job Object。本插件未实现这些 client 方法（initialize 里如实声明 `terminal: false`），agent 调用会得到 method-not-found。等真有 agent 用到再做；届时与第 4 条（后台任务保护）一起设计。
7. **工作时长 / 审批等待时长记账（P5）**。OmniTerm 在 turn 折叠处同时结算 `work_ms`（= 墙钟 − 等人审批）与 `wait_ms`：未决审批用**计数器**（`wait_depth`）不用布尔（agent 可并发发多个 `session/request_permission`），全部应答才累加该段；取消时就地结清等待段（之后的收尾算工作）。本插件落点：`streamPrompt` 已有完整 turn 生命周期，等待审批的起止点改读现行管线——询问开始是 `AgentBridge.handlePermissionRequest` 建 `PermissionLedger` 条目、广播 `permission/request` 帧那一刻（`auto` + `0` 的到达即收场没有条目，也就没有可记的等待段），结束在 ledger 的结算路径：`permission/resolved`（人答 / 取消 / 撤回）或 `announceExpiredAsk` 算出的到点答案。NTR 视图 tab 可显示每轮耗时。纯增量功能，无正确性风险。
8. **错误文案可操作化（P6）**。OmniTerm 把内部态翻译成用户动作：连接已释放时把库错误 "connection is no longer running" 替换成「会话进程已释放，请重新发送以自动恢复连接」。本插件现状：多数文案已带 agent 名与原因（如 `agent_unreachable`、npm 安装失败带输出尾部），剩余如 `session_closed` 的 "acp: session is closed" 可补一句「重新发送即自动恢复」（约束 10 的行为）。
9. **私有 prefix 的 npm 安装（P7）**。本插件已吸收全局安装形态（见「已吸收」第 5 条）；OmniTerm 的私有 prefix（`~/.omniterm/agents/node_modules/.bin`）不污染用户全局 npm、不需要全局写权限，与约束 28 同向。差异小，仅在重构 `ensureAgentExecutable` 时顺带评估。

**纪律项（非候选，保持即可）**：主动 kill 造成的 exit 事件静默。OmniTerm 的 crash watcher 对两类 exit 静默：`JoinError::is_cancelled()` 与 `alive == false`（主动关闭——killpg 造成的 "exited with signal 9" 是预期）。本插件的 identity guard（约束 11）已覆盖「延迟 exit 误判新进程死亡」的那一半；「主动释放不得触发 connectionLost」的另一半目前由 `releaseAll` 先翻转状态再 `killChild` 的顺序隐式保证。**未来新增任何 exit 触发器时必须保持这条纪律**，必要时补一条显式断言测试。

## 明确不吸收（记录理由，防止未来误判为遗漏）

- **POSIX wrapper / pid 自报 / killpg / `/proc` diff 兜底**：OmniTerm ACP 层 POSIX-only，这套东西解决的是它 crate 不交 `Child` 句柄的问题；本插件在 Windows 上有自己的完整方案（约束 26），Node 直接持有 child 对象。
- **cooked 块写回收敛**：OmniTerm 后端存原始帧、前端每轮回写折叠后的块（体积差两个数量级）。本插件的聊天持久化由宿主完成（折叠后的 assistant 消息），不存在 raw 帧落库问题。
- **usage 快照落库**：OmniTerm 的 WS 广播无补发，`usage_update` 又不被 `session/load` 重放，只能 sqlite 快照。本插件的 usage 走 `session.usage` + transcript 重放，架构下该问题不存在。
- **「权限等待不进 idle 判定」**：`isQuiet()` 已把待答审批算作忙（约束 19），同型能力已存在。
- **会话配置偏好的两层恢复**（agent 级默认 + 会话覆盖 + 恢复时逐项校验）：**曾经**判断为「`streamPrompt` 每轮 `alignSessionConfig` 已闭环同型能力」——这个判断是错的，因为 `alignSessionConfig` 只能作用于**已存在**的活会话，而对话前的选择、以及重启后的选择，都需要一个先于会话存在的记录。2026-10-17 已按「会话级 pick + 建/恢复会话时应用」吸收，见上面「已吸收」第 4 条（agent 级那一层仍不吸收，理由见该条）。
- **审批横幅队列与跨端 reconcile**（`pendingPermissions` 队列 + `permission/synced`）：审批归对话 `PermissionDock`（`conversation.input.dock`，约束 13/14），单端 UI，无多端问题。
- **权限超时三档里的 `Auto` 代答**（`pick_auto_option` 让 agent 继续）：**已吸收（2026-10-28），本条反转**。原判与约束 13/14「任何询问都必须交给人」正面冲突，现在不成立：`auto` 已是 `permissionTimeoutMode` 的受支持档位（**opt-in**，默认仍是 `wait`），到点按 option **kind 优先级**代答（`pickAutoOption`），约束 13/14 同步改写为「默认必须问人，只有部署显式选 `auto` + `0` 才由插件代答」。→ [agents/permissions.md](./agents/permissions.md) §2.1。`Abort` 档的可操作化告知本插件已有（`bridge.ts` 超时 notice 写明错过了什么），缺的只是对话内归属（并入「尚未吸收」第 3 条）；`Wait` 档的「跳过 prompt 卡死判定」本插件无对应机制（约束 23：不按空闲强制定稿），无需移植。
- **前端重连对账的 subscribe-before-snapshot 变体**：OmniTerm 客户端连接时先订阅广播再取 turn 快照，快照携带 seq 水位，实时帧 `seq <= 快照` 直接丢弃——重叠窗口变成可去重的重复窗。本插件已有 `since(seq)` 补发 + `session/reset` 水位清空，语义覆盖同一问题；此条只是去重粒度更细的变体，仅当 SSE 侧观测到重复帧时参考。
- **DSH 宿主面的能力**（会话内全文搜索、Markdown 导出、浏览器桌面通知、命令面板、服务重启 preflight、侧栏 UX）：OmniTerm 这些是它自己的前端/后端功能；DSH 宿主提供聊天显示层与自己的通知/导出面，插件只借显示层，不重复造。
- **SDK 2.x / 协议 v2 升级**：OmniTerm 的 crate 2.2.0 也握 `ProtocolVersion::V1` 握手；本插件 TS SDK 1.9.0 同为 v1 且已带 `session/list` / `.delete` / `.fork` 方法串。无落后问题，不为单点功能升级依赖。
- **`session/fork` / `session/close` / `session/resume`**：OmniTerm 自己也没做 fork（缓做，等载入链路存在）与 close（删除语义已覆盖）；resume 与 load 同能力位。都不是缺口。
- **启动超时 = drop future 的级联清理形态**：Rust 所有权特有（超时即 drop 外层 future → abort 链 → RAII 收尾）；本插件的 `withStartupTimeout` + `killChild`（约束 12）语义等价。
